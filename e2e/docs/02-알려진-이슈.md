# 이슈 기록 (E2E 작성 중 발견)

## 1. 워크스페이스 멤버를 해제한 뒤 프로젝트에 재배정하면 500 — **수정됨**

- **상태**: 수정 완료 (`fix/workspace-member-reinvite-500`). `TC-AC-014`와 백엔드 테스트
  `label_studio/projects/tests/test_members_api.py`가 회귀를 막습니다.
- **재현**
  1. 어떤 사람을 워크스페이스의 프로젝트 멤버로 배정한다 (워크스페이스 멤버가 자동으로 추가됨).
  2. 워크스페이스 멤버 탭에서 그 사람을 **해제**한다 (soft delete).
  3. 같은 사람을 다시 그 워크스페이스의 프로젝트 멤버로 배정한다.
  4. → `POST /api/projects/<id>/members/` 가 **HTTP 500**.
- **원인**

  `label_studio/projects/members_api.py:136-138`

  ```python
  existing.deleted_at = None
  existing.deleted_by = None          # ← WorkspaceMember 에는 없는 필드
  existing.role = existing.role or 'member'
  existing.save(update_fields=['deleted_at', 'deleted_by', 'role', 'updated_at'])
  ```

  `Workspace` 모델에는 `deleted_by`가 있지만(`workspaces/models.py:85`), `WorkspaceMember`에는 `deleted_at`만 있고 `deleted_by`가 없습니다(`workspaces/models.py:148`).
  없는 필드를 `update_fields`에 넣어 저장하면서 `ValueError: The following fields do not exist in this model...`가 납니다.

- **수정 내용**: `WorkspaceMember`의 soft delete는 `deleted_at`만 씁니다(워크스페이스 멤버 삭제 API도 동일).
  되살릴 때도 `deleted_at`만 되돌리도록 `deleted_by` 대입과 `update_fields` 항목을 제거했습니다.
- **영향(수정 전)**: 사람을 워크스페이스에서 내보냈다가 다시 부르는 운영 시나리오가 막혀 있었습니다.

## 2. 워크스페이스 목록이 멤버십으로 걸러지지 않음 — **수정됨**

- **상태**: 정책 변경 완료 (`feat/workspace-list-membership-filter`). `TC-AC-005`와 백엔드 테스트
  `label_studio/workspaces/tests/test_api.py`가 기대값을 고정합니다.
- **내용(수정 전)**: `GET /api/workspaces/`가 조직 범위로만 걸러져서, 워크스페이스 멤버가 아닌 사람도
  다른 워크스페이스의 **제목·설명**을 볼 수 있었습니다. 상세(`/api/workspaces/<id>/`)는 이미 404였으므로
  목록만 기준이 어긋나 있던 상태였습니다.
- **수정 내용**: 목록에도 상세와 같은 멤버십 기준을 적용하고, 조직 전체 조회는 슈퍼 관리자(조직 소유자 또는
  `super_admin` 역할)에게만 남겼습니다. 프로젝트 수 annotation이 멤버십 행 수만큼 부풀지 않도록
  members 조인 대신 서브쿼리로 걸렀습니다.

## 3. 참고: 레거시 토큰 인증 비활성화

- `GET /api/current-user/token`은 토큰을 돌려주지만, 그 토큰으로 API를 호출하면
  `401 legacy token authentication has been disabled for this organization`이 납니다.
- 그래서 이 폴더의 API 클라이언트(`lib/api.mjs`)는 **세션 쿠키 + `X-CSRFToken` 헤더** 방식을 씁니다.
  다른 스크립트를 만들 때도 토큰 방식을 쓰지 마세요.

## 4. 참고: 기존 Playwright 하니스가 `workspace` 브랜치에 있음

- `web/apps/labelstudio-e2e-playwright/` (커밋 `610d05d43`, 브랜치 `workspace`)에 별도의 Playwright 구성이 있습니다.
  계정 체계(`*@e2e.saillabel.local`)와 시드 방식(Django management command)이 이 폴더와 다릅니다.
- 이 폴더(`e2e/`)는 요청하신 `localtest_*` 계정과 워크스페이스 2개 구성을 기준으로 새로 만들었습니다.
  두 벌을 유지할 이유가 없다면 한쪽으로 합치는 것을 권합니다.
